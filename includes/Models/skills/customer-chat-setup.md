# Customer Chat Setup

## When to Use

Use this skill when an administrator asks the AI agent to set up the frontend
customer chat, public docs assistant, Docusaurus/static-site embed, or anonymous
support chat.

## Workflow

1. Inspect current setup with `sd-ai-agent/public-chat-setup` using
   `action: "status"`.
2. Confirm the admin has chosen:
   - a real AI provider/model for customer traffic, or global defaults;
   - one or more existing documentation knowledge collection slugs;
   - the exact customer/docs origin, including scheme and port when relevant.
3. If static docs are not indexed yet, guide the admin to import a trusted docs
   manifest with WP-CLI:

   ```bash
   wp sd-ai-agent knowledge import_static_docs build/docs-manifest.jsonl --collection=docs --prune
   ```

   Do not ask public/browser input to read arbitrary server paths. The importer
   expects a trusted manifest generated by the admin or CI.
4. Configure public chat with `sd-ai-agent/public-chat-setup` using
   `action: "configure"`, the selected `origins`, `collection_slugs`, and
   optional `provider_id`/`model_id`.
5. Return the generated embed snippet and explain that browser config only
   identifies the API base/embed; it never grants tools or model access.

## Safety invariants

- Keep anonymous/customer tools constrained to `sd-ai-agent/knowledge-search`.
- Never expose memory, options, files, WP-CLI, posts, users, database, uploads,
  settings, or internal `sd-ai-agent/v1` dispatcher abilities to public chat.
- Do not accept provider/model/agent/tool overrides from the browser as a source
  of authority. Server settings must win.
- Allowed origins must be exact `http://` or `https://` origins. Do not use
  wildcards.
- Public answers should cite knowledge source titles/URLs and say when docs are
  insufficient.

## Verification before telling the admin setup is done

- Build assets with `npm run build` and copy `build/embed-widget.js` plus
  `build/style-embed-widget.css` to the docs site.
- Load a logged-out static page with no `window.wp` global and confirm the widget
  renders without model picker, agent picker, session drawer, sidebar, or new-chat
  controls.
- Send a real docs prompt through the public widget or `/public-chat/*` token
  flow using the configured real model.
- Verify a non-allowlisted origin receives
  `sd_ai_agent_public_chat_origin_forbidden` from `/public-chat/session`.
- Verify logged-out requests to the authenticated `/run` endpoint remain denied.
